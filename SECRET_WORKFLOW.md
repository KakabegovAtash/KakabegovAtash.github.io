# Инструкция по работе с секретной страницей (Secret Room Workflow)

Этот документ описывает архитектуру, безопасность и пошаговый процесс редактирования секретной страницы `secret.html`. Он предназначен для разработчиков и AI-ассистентов в последующих сессиях.

---

## 1. Архитектура и Безопасность

Секретная страница предназначается для хранения личного контента (календарь разлуки, счетчики, сюрпризы). Для обеспечения 100% конфиденциальности при публикации на GitHub Pages используется следующий подход:

1. **Исходный код (`secret_src/secret_raw.html`)**: Содержит полный открытый HTML, CSS, JS и личные данные (`RAW_SECRET_DATA`). **Находится в `.gitignore`** и НЕ коммитится в репозиторий.
2. **Зашифрованный файл (`secret.html`)**: Публичный файл, находящийся в корне репозитория. В нем нет открытого текста. Он содержит только UI формы входа (заглушку с полем ввода пароля) и зашифрованный Base64-блок данных.
3. **Алгоритм шифрования**: Потоковый шифр RC4 с UTF-8 кодированием ключа и данных. Разблокировка происходит прямо в браузере на стороне клиента с помощью JavaScript (`DOMParser` + динамическое воссоздание `<script>`).
4. **Отсутствие ссылок на главном сайте**: На `index.html` нет кнопок и ссылок на `secret.html`. Доступ возможен только при значении прямого URL (`.../secret.html`).

## 2. Структура файлов

```
Portfolio-site/
├── secret_src/             # [ИГНОРИРУЕТСЯ GIT] Папка с исходными секретными файлами
│   └── secret_raw.html     # Открытый исходник секретной страницы
├── build_secret.py         # Скрипт сборщика и шифрования (Python)
├── secret.html             # Итоговый зашифрованный файл (Коммитится в Git)
├── .gitignore              # Содержит правило: secret_src/
└── SECRET_WORKFLOW.md      # Данная инструкция
```

## 3. Пошаговый порядок внесения изменений

Когда необходимо обновить контент, добавить новые сюрпризы, цитаты или изменить дизайн секретной комнаты, следуйте этой инструкции:

### Шаг 1. Редактирование исходника
Вносите все изменения **ИСКЛЮЧИТЕЛЬНО** в файл:
`file:///home/atash/Portfolio-site/secret_src/secret_raw.html`

*Не редактируйте `secret.html` вручную — он полностью перезаписывается скриптом сборки.*

### Шаг 2. Сборка и шифрование страницы
Запустите Python-скрипт `build_secret.py` из корня проекта.

**Вариант А (с передачей пароля аргументом):**
```bash
python3 build_secret.py PUPUNKA
```

**Вариант Б (с интерактивным вводом пароля):**
```bash
python3 build_secret.py
```
*(Скрипт попросит ввести и подтвердить пароль без отображения вводимых символов).*

Скрипт выполнит RC4-шифрование `secret_src/secret_raw.html` и сформирует обновленный файл `secret.html`.


> ⚠️ **КРИТИЧЕСКИ ВАЖНО**: 
> - Убедитесь, что папка `secret_src/` остаётся в `.gitignore`. Никогда не удаляйте её из `.gitignore` и не используйте `git add -f secret_src/`.
> - Никогда не хардкодьте пароли в `build_secret.py` или любых других файлах репозитория.

---

## 4. Важные технические детали для AI-ассистента

- **Совместимость кодировок**: В `build_secret.py` и в клиентском JS используется `TextEncoder` / `TextDecoder` для правильной работы с кириллицей в паролях и тексте.
- **Изоляция скриптов**: При расшифровке скрипты из `secret_raw.html` исполняются динамически. Код заглушки шифрования обернут в IIFE `(function() { ... })();`, чтобы избежать конфликтов глобальных переменных (`const`, `let`).
